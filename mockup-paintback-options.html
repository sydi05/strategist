One-way capture. When the sponsor marks a selection here, the plugin reads the chosen option ID, conditions, and rationale, then calls the agent's selection-update routine. The agent writes the selection block to the schema; the canvas can't be edited after.
Why this paint-back doesn't round-trip. Outputs 1–4 paint-backs are round-trip iteration surfaces — sponsors edit, comments flow back, agent revises to v2. Output 5 is fundamentally different: the sponsor isn't editing the options, they're choosing among them. There is no "what if we change OPT-B's gains?" — that would be the strategist re-shaping the option set, not the sponsor editing on canvas. The selection panel exists; it does one thing: capture which option won, with what conditions, for what stated reason. Then the schema versions to v2 with the selection block populated.
Paint-back conventions
Horizontal baselines aligned
Each row (target state, gains, gives_up, horizon, confidence, value drivers, cost, benefit) sits on the same horizontal baseline across all options. Sponsors compare directly — visual scan rather than reading.
Cost in AUD · benefit in % of VD impact
Cost is ROM in AUD ranges from Salesforce effort references (purple stripe). Benefit is cumulative percentage of value driver impact by horizon (green stripe). AUD conversion of benefits happens only at Output 10 (Business Case) — strategist doesn't invent dollar benefits.
Feasibility validation visible per option
Every option's cost profile shows Feasibility's verdict — validated / flagged for Stage 2 / rejected. Mandatory consultation before publishing. Sponsors see which options have a wider error bar on cost.
Gives_up gets equal visual weight to gains
Most decks soft-pedal trade-off costs. This frame doesn't — gives_up gets its own colour-coded callout matching gains in visual prominence.
Selection panel is the only interactive element
Three radio-style selectors plus two free-form zones (conditions, rationale). Selection is mutually exclusive. No other element on this canvas is editable.
Schema versioning happens after selection
When the sponsor marks a selection, the plugin extracts the option ID, conditions, and rationale stickies. The agent writes them into the canonical schema's selection block. The deck regenerates in post-selection state.
